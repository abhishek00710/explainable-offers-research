## Exact reader commands

From a new checkout or extracted release root:

```sh
python3 scripts/verify_release.py
python3 scripts/scan_disclosures.py
python3 scripts/check_metrics.py
./scripts/reproduce.sh runs/fresh
```

The last command refuses an existing output directory. To repeat, choose another name, for example `runs/second`. It invokes:

```sh
swift test --package-path artifact --disable-sandbox --scratch-path "$BUILD/original"
swift test --package-path artifact/Validation --disable-sandbox --scratch-path "$BUILD/validation"
# Executed from artifact/:
swift run -c release -debug-info-format none --disable-sandbox \
  --scratch-path "$BUILD/original" offer-experiments \
  --seed 20261119 --count 2160 --output "$OUT/original"
# Executed from artifact/Validation/:
swift run -c release -debug-info-format none --disable-sandbox \
  --scratch-path "$BUILD/validation" validate-offers "$OUT/validation"
```

Here BUILD and OUT describe the actual unique temporary build root and requested new output directory created by `scripts/reproduce.sh`; use the wrapper for executable commands with correctly assigned paths. The wrapper also runs the original and Validation Python audits, follow-up table generator, historical manuscript checks, and deterministic comparisons. `--disable-sandbox` addresses nested SwiftPM sandboxing; it does not disable the enclosing machine's controls. `-debug-info-format none` avoids the previously recorded `dsymutil` problem without changing release optimization.

## Remaining risks and owner decisions

1. **Disclosure rights:** source inspection cannot determine employer/institution obligations or whether the recorded OS/toolchain releases were prerelease/confidential under the owner's accepted agreements. Confirm permission to disclose the code, environment and measurements before publishing. No public-release-status claim for those versions is made here.
2. **Ownership:** the owner approved licensing material they own. The scan found no proprietary banking-code indicators, but cannot establish chain of title or prove an absence of confidential information. No warranty of legal clearance is implied.
3. **Scan limits:** credential patterns and URL allowlisting are heuristic. They are paired with manual module/resource review; undetected secrets or contextual confidentiality remain possible. Approved copyright attribution is intentionally public personal information. Generic system/scratch paths are documented and retained; private home and per-user temp paths are redacted.
4. **Scientific limits:** 36 authored cases and 24 authored ranking scenarios are not representative customer samples. Labels are classifier-independent in execution, not blinded or independently annotated. Conflict rejection benefits are conditional on the controlled pool's correct token evidence. Seed ranges are not confidence intervals. No significance, production uplift, customer outcome or iOS speed claim is justified.
5. **Reproducibility scope:** fresh-checkout success was verified on this macOS host only. Minimum deployment target 13 and Swift tools version 6.0 do not establish compatibility across all earlier environments; NLTokenizer behavior may change by OS. Benchmarks/RSS/log durations vary.
6. **Publication metadata:** no DOI, accepted-paper status, author affiliation, versioned public URL or publication citation has been invented. Add actual metadata once available. Check publisher policies for any later manuscript text added to the repository.
7. **Approval gate:** no GitHub creation, remote push or publication has occurred. The owner must explicitly approve any such next action. Apache-2.0 approval does not itself authorize publication.
