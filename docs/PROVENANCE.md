# Evidence preservation and public-copy policy

The original ExplainableOffers project remains unchanged. The release is a separate derived copy, with the experiment packages under `artifact/` and new release documentation at the top level.

The source inventory records 128 files, including one Finder `.DS_Store` metadata file. That binary was retained locally but excluded from distribution. Sixteen historical log files contained personal home-directory paths and, in some cases, per-user temporary directories. An additional escaped per-user temporary path was found in one historical environment JSON command-argument field and redacted. Only those path strings were redacted in public copies, using `<USER_HOME>` and `<TEMP_PATH>` placeholders. Failures, timings, test counts, compiler versions, and all measured values remain visible. These are clearly labeled derivatives, not claimed to be byte-identical raw logs.

All experimental Swift/Python source, frozen inputs, reports, CSV files and manuscript tables are unchanged from the source project. Neither unfavorable results nor failed build evidence was deleted. Generic system executable/SDK paths and portable scratch examples (`/tmp`, `/usr/bin`, `/Applications/Xcode.app`) remain where necessary for reproducibility. Relative recorded executable paths also remain; they do not contain an individual's home directory.

`provenance/source-inventory.json` maps each original relative path and SHA-256 to its released version and transformation. The original source hashes establish custody without distributing personal path text. Historical hash manifests are retained separately under `provenance/historical-manifests/`. Four active manifests were regenerated for the sanitized artifact tree: the original two results manifests, Validation's original-file baseline, and Validation's aggregate manifest. They describe the public copy and must not be mistaken for the pre-redaction hashes. Historical audit logs retain their original claims in historical context. Public re-audits validate the sanitized baseline.

New reproduction runs write into ignored `runs/` directories and do not overwrite `artifact/results` or Validation outputs. Test/build logs produced by a user's own machine may contain local paths; the release verification logs have the same path redaction applied. Numerical fresh-run comparisons remain exact for deterministic files. Benchmark times, RSS, timestamps and build/test durations are expected to vary; the supplied original observations are not replaced.

`provenance/release-sha256.json` covers the assembled release except itself, Git metadata, ignored run outputs and Python caches. `scripts/verify_release.py` checks both file hashes and inventory. License/NOTICE additions affect only the release copy and do not rewrite historical source headers or evidence. Hash regeneration is an explicit maintainer action, not an audit workaround.
