# Threats to validity and appropriate use

**Construct validity.** Transaction-level category accuracy is not recommendation usefulness. Out-of-scope ground truth and classifier abstention share the `unknown` symbol: correct unknown outcomes raise six-label accuracy while lowering coverage. Report both, alongside five-class macro-F1 and classified-only performance. Conditional accuracy can reward selective abstention and must never be substituted for all-record performance. NDCG uses authored ordinal judgments, not observed preferences. Template explanations are traceable but their understandability, trust effects and accessibility have not been tested with people. Higher spending does not imply need, benefit or willingness to spend.

**Internal validity.** The same author designed the rules, merchant cases and scenarios. Labels are independent of rule execution, but example selection is not blinded. Known aliases favor tokens; selected metadata corruption penalizes metadata-first precedence. Prefixes and punctuation cover a small manual vocabulary. The frozen file detects regressions, not experimental leakage. The Python audit independently recomputes numeric metrics from exports but does not independently establish label correctness. Nine benchmark trials share one process and cache state. Rotating method order reduces one simple order effect but does not control thermal state, power mode, OS activity, framework caching or compiler optimization. The checksum consumes results but is not a universal guarantee against every compiler optimization.

**External validity.** This is a macOS command-line package using an Apple framework, not an iOS banking integration. No device, network, service latency, production transaction stream, model deployment, customer experiment or bank's production implementation was tested. Synthetic amounts and class balance are arbitrary. A single host, OS and Swift toolchain cannot represent mobile hardware or cross-version tokenization behavior. Five categories omit many merchant types and mixed baskets. No multilingual or arbitrary typo robustness claim is warranted. Missing reversal links and unavailable authoritative updates cannot be corrected from descriptions. Stale-but-within-TTL decisions remain possible; TTL is an assumption, not proof that eligibility remains current.

**Statistical conclusion validity.** There are 36 underlying classification cases and eight ranking scenarios, not thousands of independent merchant samples. No confidence intervals, hypothesis tests, significance claims or population effect sizes are reported. Benchmark percentiles use the nearest-rank convention; with nine trials P90 equals the maximum. They describe these samples only. Whole-process peak RSS includes classification export and framework initialization and cannot support per-method memory efficiency comparisons. Mean NDCG equally weights deliberately constructed scenarios; conclusions can change with a different scenario mix or eligible-only ordering.

**Reproducibility.** The seed, fixed clock, ordered cases, frozen fixtures, raw predictions, trial timings, environment, source/fixture SHA-256 hashes and console logs support rerunning and inspecting the experiment. Timing, RSS, wall-clock run timestamp, host paths and build logs are expected to vary. NLTokenizer is an OS framework whose behavior may change; reproducibility is conditional on runtime/toolchain. Package deployment target is macOS 13, but only the recorded macOS host was exercised. The rules were not tuned after inspecting accuracy results in this run; corrections during development addressed compilation, instrumentation and tests.

**When inferior or inappropriate.** Metadata-first can propagate incorrect categories even when description aliases are correct. Token rules can misclassify donations containing merchant-like words, abstain on new merchants, and overgeneralize ambiguous text. Profile ranking can be worse than an eligible-only list when current needs diverge from historical spending. A neutral list is preferable when signals are absent; no list is returned when authoritative eligibility cannot be established. Neither ranking is suitable as an authorization, credit, affordability, fraud, financial-advice or eligibility decision engine. The prototype does not implement authenticated services, consent, secure storage, accessibility review, revocation delivery, cross-device account transitions or operational monitoring.
