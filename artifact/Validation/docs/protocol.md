# Frozen follow-up protocol (specified before outcome inspection)

Preserve every pre-existing repository file byte-for-byte. The standalone Validation package compiles verified identical copies of the original OfferCore/Evaluation files, plus an additive conflict-aware policy. Original labels and aliases are not edited. No original result is overwritten.

## Sensitivity intervention

Use the original 2,160-record seed-20261119 dataset. The controlled pool consists only of rows with a known gold spending category and an originally present known structured category: 600 rows, 120 per class. Preserve metadata missingness, merchant IDs, descriptions, transaction identities, amounts, gold labels, and the remaining 1,560 rows. At 0% controlled corruption replace the pool's original metadata with its gold category. This is an explicitly oracle-clean constructed condition, not the original experiment. The original unknown/out-of-scope metadata remains untouched. Thus 0% controlled error does NOT mean zero error in all metadata.

Construct 0, 5, 10, 20, 40, 60, 80, 100% incorrect categories within each 120-row class stratum. Seeds 11, 29, 47, 71, 101 generate independent deterministic SplitMix64 permutations. Corruption sets are nested across rates within seed; fixed random offsets select one of the other four known categories uniformly modulo four. Selection never inspects classifier predictions, text aliases or metrics. Gold labels set the experimental channel and prevent accidentally correct substitutions; this does not regenerate ground truth. Full assigned categories are exported. Observations are repeated variants of 36 cases, not independent real merchants. Seeds measure allocation sensitivity, not sampling uncertainty or real-world prevalence. No significance tests or confidence intervals.

Compare metadata, tokens, combined, and conflict_abstain. Conflict abstention requires BOTH channels to assert a non-unknown category and to disagree. Missing/ambiguous token evidence does not veto metadata; agreement can still be jointly wrong. This is a conservative rejection policy, not an error correction model. Profile construction reuses the original safety filtering and replaces only admitted contribution classifications. It is an evaluation adapter and has no optimized timing claim.

Primary analysis: original data, plus full 2,160-row dataset at each controlled rate/seed; secondary: 1,800 known-label rows, 600 intervened rows, and classified-only rows. Export six-by-six confusion counts, accuracy with correct counts/denominators, coverage, abstention, per-class metrics, micro/macro across six outcomes and five spending categories. Macro-F1 is the arithmetic mean of per-class F1, not F1 of mean precision/recall. Zero denominator metrics use zero; an empty subset's conditional accuracy is NA. Unknown gold is out-of-scope; predicted unknown is abstention even when correct.

## Ranking

Keep eight original scenarios separate from additional authored scenarios. Freeze additional inputs and ordinal judgments before executing comparisons. Include empty and sparse histories, preference drift, correct/incorrect/conflicting/jointly wrong metadata, and absent/stale/cross-account eligibility, mixed denied/missing/unknown decisions, expired/future/wrong-currency offers, and no-relevant-candidate cases. Define expected eligible sets independently, not from the ranker's output. NDCG@3 ideal set uses those expected candidates. Empty-candidate or zero-ideal-gain scenarios have undefined quality (NA) and are excluded from quality means with explicit counts, while remaining in safety checks. P@3 divides by three when defined, even with fewer than three candidates. No eligible candidates must be represented as a safety success, not high ranking quality.

Report original-eight, new-only and pooled descriptive means; retain per-scenario outcomes. Do not retune grades after inspecting metrics. No new timing comparison; original release benchmarks remain limited to their recorded macOS environment and exclude iOS, production and customer outcomes.
